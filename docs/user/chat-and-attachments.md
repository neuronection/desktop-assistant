# Chat and attachments

## Streaming replies

Replies stream token by token. The renderer handles markdown, syntax
highlighting for code, math via KaTeX, and diagrams. While a reply is
streaming the composer's send button becomes **Stop generating**; stopping
keeps the partial text.

A turn is owned by the main process, so hiding the window, switching to
the desktop window, or resuming after an approval never loses the stream.

## Attachments

Attach from the composer toolbar or by dropping files onto either window.

| Attachment | Notes |
|---|---|
| **Images** | Sent to the model as images; require a vision-capable model |
| **PDF** | Text is extracted; `extractText` is the default strategy |
| **Screen capture** | Capture a full screen, a region, or a specific window |
| **Selection** | Optional "insert my selection" button (X11 Linux only) |
| **Clipboard** | Optional offer-on-summon chip (nothing is read unless you click it) |

The composer shows a summary like "2 attached"; remove one with its
remove button before sending.

### Screen capture

Choose **Share screen** in the composer toolbar to open the picker. Pick a
screen or window, then optionally choose a region. High-resolution
captures are available for detailed questions. Screenshot results reach
the model as images, so a vision model must be assigned (see
[settings](settings.md#api-settings)).

### Selection insert

Enable **Settings → General → Show "insert selection" button** to add a
button next to the microphone that inserts the text you selected in
another application. It reads the X11 PRIMARY buffer on click only — it
never injects keystrokes and never touches your clipboard. Linux/X11 only.

### Clipboard offer

Enable **Settings → General → Offer clipboard on summon**. When the
launcher opens and the clipboard changed since last time, a chip offers to
ask about it. The clipboard is only read when you click.

## Conversations and history

- Conversations are stored locally in SQLite and listed in the launcher
  history and the desktop sidebar.
- **Auto-titles** — after the first exchange a title is generated by the
  assigned titles model; without one, the opening message is used.
- **Search** — the desktop sidebar and history menu let you find
  conversations.
- **Per-conversation model override** — in the desktop inspector, set a
  model for this conversation only; empty means the default model.
- **Per-conversation persona** — the inspector's **Persona** field is
  composed on top of the provider system prompt, for this conversation
  only. The launcher keeps the global prompt.

## Export

From the desktop inspector, **Export** writes the conversation as
**Markdown** or **JSON** using a save dialog.

## Long turns and partial answers

The agent has step, token and wall-clock budgets. If it hits one, it does
not fail: it salvages what it has into a single bounded answer and shows
an amber notice such as "Partial answer — the step budget was reached
before the investigation completed." The partial answer is persisted as
the turn's answer.

When a conversation grows too large for the model's context window, the
oldest whole turns are dropped to fit and a **"Older context trimmed"**
trace step records the silent loss.

## Resumable turns

Agent state checkpoints into the local database. If a turn pauses at an
approval and the app restarts, the turn can resume on the same thread.
Replayed steps are marked **resumed** in the trace so they are not
mistaken for duplicate work.

## Multi-step flows

`/research <topic>` runs a bounded research graph — plan, search, read,
assess, synthesize — narrated live as node steps in both windows and
ending in a cited report. Web reads inside the flow follow the same
approval gates. See [commands](commands.md#research).
