# Chat and attachments

## Streaming replies

Replies stream token by token. The renderer handles markdown, syntax
highlighting for code, math via KaTeX, and diagrams. While a reply is
streaming the composer's send button becomes **Stop generating**; stopping
keeps the partial text.

A turn is owned by the main process, so hiding the window, switching to
the desktop window, or resuming after an approval never loses the stream.

## Attachments

Attach from the composer toolbar or by dropping files onto either window.

| Attachment | Notes |
|---|---|
| **Images** | Sent to the model as images; require a vision-capable model |
| **PDF** | Text is extracted; `extractText` is the default strategy |
| **Screen capture** | Capture a full screen, a region, or a specific window |
| **Viewing an image** | Click any attached image (the chip thumbnail) to open it in its own window |
| **Image actions** | In the viewer: copy the image, OCR the text, crop, redact, or lasso a region (capture and uploaded images alike) |
| **Selection** | Optional "insert my selection" button (X11 Linux only) |
| **Clipboard** | Optional offer-on-summon chip (nothing is read unless you click it) |

The composer shows a summary like "2 attached"; remove one with its
remove button before sending.

### Screen capture

**Share screen** (composer toolbar) opens a grid of the modes this machine can
actually do — a mode that cannot work here is absent from the grid, not
disabled:

| Tile | Result |
|---|---|
| **Text** | A region, read as text straight away |
| **Rectangle** | The operating system's own region tool (only when one exists) |
| **Window** | That window, captured from its own pixels (never occluded) |
| **Screen** | That display, captured from its own source |
| **Full screen** | Everything, as one image |

There is no custom full-screen selection surface: a region is the OS tool you
already know, a window is picked by name, and the capture lands in the draft
chip with its name ("Firefox — GitHub", "Region 820×460"). Click the chip
thumbnail to open the image full-size; **Edit → Crop / Redact** adjusts it
before sending (see below). The same engine is on the HUD knob (**Capture screen**), on two
optional hotkeys (Settings → Hotkeys: *Capture screen* uses the window under
the pointer; *Capture screen region* runs the OS region tool), and on the
`screen_capture` agent tool — where the assistant can either take the display,
name a window, or ask you to select an area.

On Wayland the OS picker is the source list, so the rows come from the portal.
Without a native region tool the area row is simply absent (never a broken
button).

### Selection insert

Enable **Settings → General → Show "insert selection" button** to add a
button next to the microphone that inserts the text you selected in
another application. It reads the X11 PRIMARY buffer on click only — it
never injects keystrokes and never touches your clipboard. Linux/X11 only.

### Clipboard offer

Enable **Settings → General → Offer clipboard on summon**. When the
launcher opens and the clipboard changed since last time, a chip offers to
ask about it. The clipboard is only read when you click.

## Conversations and history

- Conversations are stored locally in SQLite and listed in the launcher
  history and the desktop sidebar.
- **Auto-titles** — after the first exchange a title is generated by the
  assigned titles model; without one, the opening message is used.
- **Search** — the desktop sidebar and history menu let you find
  conversations.
- **Per-conversation model override** — in the desktop inspector, set a
  model for this conversation only; empty means the default model.
- **Per-conversation persona** — the inspector's **Persona** field is
  composed on top of the provider system prompt, for this conversation
  only. The launcher keeps the global prompt.

## Branches and variants

A conversation is a tree, not a single overwritten transcript:

- **Edit** a user message to send a corrected prompt. The edit becomes a
  new sibling under the same parent and the conversation moves to it; the
  original question and its answer stay available as variants.
- **Regenerate** an assistant reply to create a new answer under the same
  user message. The previous answer stays available as a variant.
- Use the **‹ n/N ›** switcher under a branched message (launcher compact
  mode shows it under the answer) to move between variants.
- The desktop inspector's **Branches** rail shows the whole tree; click a
  node to switch the visible path.

Only the active path is sent to the model. If a second turn is started
while one is running, it is queued — a conversation never streams two
turns at once. Editing while an approval is open completes the approval
on the old branch, then runs the edited branch fresh.

## Export

From the desktop inspector, **Export** writes the whole conversation tree
as **Markdown** or **JSON** using a save dialog. Both formats include every
branch; the Markdown marks nodes on the active path, and the JSON carries
`parentId`/`activeChildId` plus variant metadata. The model context and
normal transcript remain active-path-only.

## Long turns and partial answers

The agent has step, token and wall-clock budgets. If it hits one, it does
not fail: it salvages what it has into a single bounded answer and shows
an amber notice such as "Partial answer — the step budget was reached
before the investigation completed." The partial answer is persisted as
the turn's answer.

When a conversation grows too large for the model's context window, the
oldest whole turns are dropped to fit and a **"Older context trimmed"**
trace step records the silent loss.

## Resumable turns

Agent state checkpoints into the local database. If a turn pauses at an
approval and the app restarts, the turn can resume on the same thread.
Replayed steps are marked **resumed** in the trace so they are not
mistaken for duplicate work.

## Multi-step flows

`/research <topic>` runs a bounded research graph — plan, search, read,
assess, synthesize — narrated live as node steps in both windows and
ending in a cited report. Web reads inside the flow follow the same
approval gates. See [commands](commands.md#research).

In the desktop Inspector, select the model under its provider when two providers advertise the same model ID. The next turn displays the provider and model, and explicit selections stay with the conversation. Setup and task defaults also keep the provider with the model. Older conversations without a saved provider continue to use the first configured match until you choose a provider.
